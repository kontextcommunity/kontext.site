# kontext.stage — сайт плагина для TouchDesigner

Ты работаешь над лендингом kontext.stage: чат-панель внутри TouchDesigner, через которую агент (Claude Code, Codex или API-модель) строит сеть, проверяет её и сохраняет для команды в одном `.tox`. Сайт уже собран и работает. Задача — дорабатывать его по моим запросам, не ломая механику, токены и структуру.

## Файлы

```
kstage-site/
├── index.html        вся вёрстка, CSS (13 пронумерованных блоков) и JS в одном файле
├── docs/SPEC.md      спека: карта страницы, токены, движок, анимации с таймингами, адаптив, ловушки
└── CLAUDE.md         этот файл
```

Картинок нет: все визуалы — процедурные канвасы (`ARTS` в JS).

`docs/SPEC.md` — источник правды. Прочитай его целиком до первой правки. Если меняешь механику, тайминг или структуру, обнови нужный раздел SPEC.md в той же правке.

## Референс

https://www.paulkalkbrenner.net/ — по нему собрана механика: вордмарк с окном-картинкой, которое сжимается в слово; сетка колонок 01–09 с точками в заголовке; перетаскиваемая бегущая строка; пиксельный переход 25×4 внизу медиа-секций в цвет следующей; «падающая» стопка карточек; архив-слайдер со счётчиком; гигантская цифра поверх визуала; CTA с лентой превью и ячейками-кнопками; курсор-пузырь; фиксированная навигация.

Правила работы с референсом:
- только смотреть и измерять поведение: тип эффекта, дистанции, кривые, длительности, сетку;
- не копировать его HTML, CSS, JS, тексты, фото, логотипы и шрифты — всё делается своим кодом;
- контент только kontext.stage: тексты из гайда плагина или то, что я пришлю. Ничего не придумывать про функции — если факта нет в гайде, спроси.

Как измерять (Chrome DevTools или Playwright, 1440×900): найди элемент в DOM, сними `getComputedStyle().transform / opacity / transition` и `getBoundingClientRect()` в нескольких моментах времени или положениях скролла; правила CSS — через `document.styleSheets`.

## Правила кода

- Стек: HTML/CSS/JS + Lenis 1.1.13. Без GSAP, React, сборщика и новых библиотек без моего согласия.
- Цвета, шрифты, кегли, кривые — только через токены `:root`. Палитра kontext.: `--cream`, `--ink`, `--gray`, `--red`. Новых цветов не добавлять.
- Цвет секции — модификаторы `.sec--gray / --red / --ink`. Цвет пикселей перехода — `--to` на медиа-секции, равен фону следующей.
- Один `requestAnimationFrame` на сайт (`raf()`). Новые scrubbed-эффекты — туда, позиции секций — в `measure()`. Скролл читать из `scrollY`, не из `lenis.scroll`.
- Канвасы только через `register(canvas, art, speed)`: так они рисуются лишь на экране и пересчитываются при resize. DPR ≤ 1,5.
- Контент списков — в массивах CONFIG вверху скрипта (`CONTACT`, `AGENTS`, `ALSO`, `BEFORE`). Остальное — HTML.
- Копирайт на английском: коротко, конкретно, без маркетинговых штампов. Имена инструментов агента — в `<code>`.
- Сохраняй: `prefers-reduced-motion`, 100svh, `<meta charset="utf-8">`, aria-атрибуты, фокус с клавиатуры у стопки и аккордеона.
- Адаптив: 1440, 900, 390 px без горизонтального скролла.

## Как проверять

1. Только через сервер: `cd kstage-site && python3 -m http.server 8767`.
2. После правки — скриншоты Playwright на 1440×900 и 390×844: hero на 0,3 / 1,2 / 2,2 с; затем всю страницу шагом 0,8 экрана. Отдельно: клик по пилюле режима, клик по стопке (кадр через 250 мс и через 1,2 с), открытие строки аккордеона, пиксельный переход на 0 / 40 / 60% прохода. Консоль без ошибок.
3. Сам посмотри на скриншоты, прежде чем сказать, что готово.

## Формат ответа

Коротко, по-русски: что поменял, в каких блоках `index.html`, что проверил. Если решений несколько — дай 2–3 варианта и жди выбора перед большой переделкой.
