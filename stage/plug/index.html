One panel. Three brains.
Permissions you can see.

  1. 01
    Inside TouchDesigner

    The panel opens in a pane, a floating window or the browser. All work happens in stage_work next to the component.

  2. 02
    Three brains in one panel

    Claude Code on your Claude subscription, Codex on your ChatGPT plan, and 13 API providers. Switch in settings, no reinstall.

  3. 03
    Permissions in the chat

    Ask, Plan, Auto and Bypass. Every risky action shows up in the chat: allow it, deny it, or allow it for the whole chat. Switch from the pill or with Shift+Tab.

  4. 04
    One file for the team

    The component saves to a single .tox with settings inside. Drop it into a network and it starts on its own. Keys and tokens never go into the file.

Functions

Six parts, one component. Open a row to see what it does.

What itdoes

  • Agent replies, tool calls and the status “thinking / building / waiting” appear in the feed.
  • Stop, new chat, Undo, message draft, copy reply.
  • Text you select in TouchDesigner goes to the agent as context.
  • Mouse-wheel scrolling, smooth transitions, and a look that matches TouchDesigner.
  • Claude Code runs the Claude Code installed on your machine, on your subscription. Model, effort, step count and toolset are configurable.
  • Codex runs Codex CLI on your ChatGPT plan or an OpenAI key, in a read-only or workspace-write sandbox.
  • API works with any OpenAI-compatible provider. The model list loads from the provider.
  • Ask asks before every change.
  • Plan shows a plan first and builds after you approve it.
  • Auto allows TouchDesigner tools and asks about everything else.
  • Bypass asks nothing. For tests, not for the team.
  • Every change goes to stage_work. Deleting anything outside it needs your confirmation.
  • Create and connect nodes, set parameters, run Python inside TouchDesigner (with confirmation in Ask mode).
  • Check the network for errors, export it to text, and describe any operator by its type.
  • Agent, permissions, tools, project memory, knowledge base and its repository, cloud or local image processing.
  • The Doctor button checks the install, the sign-in and that every component is reachable.
  • The installer builds the component and saves it as a .tox.
  • Package export saves the component with stage_work and settings — without keys.
  • On load, the component starts its server, creates the work folder and opens the panel.
